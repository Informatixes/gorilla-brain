# Contribuir

1. No incluyas contenido real de clientes en ejemplos, pruebas o plantillas.
2. Mantén las preguntas orientadas a hechos que el usuario conozca.
3. No preguntes al usuario cómo diseñar RAG, agentes, nodos, taxonomías o arquitectura.
4. Conserva el límite de una ronda conjunta de aclaraciones por fase.
5. Añade un escenario de evaluación cuando cambies un comportamiento.
6. Ejecuta `npm test` antes de proponer un cambio.

Los cambios deben ser pequeños, trazables y compatibles con la estructura portable de Agent Plugins 1.0.
